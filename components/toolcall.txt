# DsToolCallStep — Cogniterm Design System

import { DsToolCallStep } from '~/design'   // Vuetify 불필요 · ds.css만

## 용도
에이전트가 도구를 쓸 때마다. 실패한 단계도 그대로 보여줍니다.

## Props
- status: 'running' | 'done' | 'error' = 'running' — 진행 중 스피너 / 완료 체크 / 실패 ✕.

## Slots
- #default — 실행 내용. 도구 이름과 인자를 그대로 보여줍니다.

## 사용 예
```vue
<DsToolCallStep status="done">search_drive("계약서", June) — 3 files</DsToolCallStep>
<DsToolCallStep status="running">read_document("계약서_최종.pdf")</DsToolCallStep>
<DsToolCallStep status="error">extract_table("스캔본.pdf") — 텍스트 레이어 없음</DsToolCallStep>
```

## HTML 문법 — Vue 없이 문자열로 그리는 화면
```html
<!-- 진행 중 -->
<div class="toolcall"><span class="spinner"></span> read_document("file.pdf")</div>

<!-- 완료 -->
<div class="toolcall"><span class="check"><svg class="lic " width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" aria-hidden="true"><path d="M20 6 9 17l-5-5"/></svg></span> search_drive("query") — 3 files found</div>
```

## 앱별
- 이용자 화면 (Vuetify 있음): 이 부품 그대로
- 관리자 콘솔 (Vuetify 없음): 이 부품 그대로 (~/design · html 문법)


## 지침
- [해야 할 것] 원칙 4 — 접을 수는 있어도 없애지 않습니다. 항상 열어볼 수 있게 합니다.
- [해야 할 것] 실패한 단계도 그대로 보여줍니다. 무엇이 안 됐는지 아는 것이 사용자에게 유용합니다.

## 접근성
직접 처리: 진행 → 완료 전환 시 aria-live로 알리기 / 실패한 단계를 숨기지 않기

## 시스템 규칙 (요약)
- 색·간격·모서리는 제품 토큰만 (var(--border), var(--primary), var(--r-el)) — hex 금지. --brand · --sel-bg 는 문서 사이트 전용이라 앱에 없습니다
- primary 버튼은 화면당 하나. 활성(탭·필터)은 --nav-active 선+글자, 목록 행 선택은 --selected-fill 회색 면
- 컨트롤 높이 32(기본) / 28(sm — 필터 바·툴바) / 40(lg — 로그인 제출 전용)
- 목록·테이블은 default/loading/empty/error/partial 5상태
- 전체 규칙: https://Cogniterm.github.io/design-system/llms.txt
